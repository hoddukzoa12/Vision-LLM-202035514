# Project03: 공부 집중 도우미 (Study Focus Assistant)

## 개요
책상 위 카메라와 마이크로 공부하는 학생을 지켜보는 Vision-LLM 시청각 멀티모달 시스템입니다.
YOLO로 **휴대폰 사용**과 **자리비움**을, 마이크로 **주변 소음**을 감지하면 Gemma가 상황에 맞는 한마디를 만들어 음성으로 말합니다.
화면에서 `s` 키를 누르고 질문하면, 현재 책상 상황과 집중 통계를 바탕으로 Gemma가 음성으로 대답합니다.

| 이벤트 | 감지 조건 | 입력 | 응답 |
|---|---|---|---|
| `phone` 딴짓 | 휴대폰이 3초 이상 계속 보임 | 카메라 (YOLO) | 다시 집중하라는 한마디 |
| `absent` 자리비움 | 사람이 10초 이상 안 보임 | 카메라 (YOLO) | 자리비움 알림 |
| `noise` 소음 | 소음 기준 초과가 2번 연속 (5초마다 측정) | 마이크 (음량) | 조용한 환경을 권하는 한마디 |
| `question` 질문 | 화면에서 `s` 키 | 마이크 (STT) | 질문에 대한 답변 |

## 실행 방법

```bash
cd ~/vision-llm
source .venv/bin/activate

# 0) (처음 한 번) 마이크 카드 이름 확인: "card N: Microphone [...]"의 이름이 다르면 voice.py의 MIC_DEVICE(CARD=) 수정
arecord -l

# 1) (처음 한 번) 마이크 입력 키우기 (기본 16은 말소리가 조용할 때보다 4~5 dB만 커서 구분이 어려움)
amixer -c Microphone sset Mic 24

# 2) (처음 한 번) 소음 기준 정하기: 조용할 때와 떠들 때 값을 보고 assistant.py의 NOISE_THRESHOLD_DB 수정
python3 Project03/voice.py

# 3) 실행 (Assistant와 Vision을 함께 켬)
python3 Project03/main.py
```

디버깅할 때는 두 터미널에서 따로 실행할 수 있습니다: `python3 Project03/assistant.py`, `python3 Project03/vision.py`

| 키 (카메라 창) | 동작 |
|---|---|
| `s` | 음성 질문 ("네, 말씀하세요." 뒤 5초 녹음) |
| `q` | 종료 (`main.py`로 실행했으면 Assistant도 함께 종료) |

## 구현 설명

### 1. 프로세스 분리 (06 A-7)
YOLO와 Gemma를 한 프로그램에서 돌리면, Gemma 추론과 5초 녹음 동안 카메라 화면이 멈춥니다.
그래서 수업처럼 두 프로세스로 나누고 JSON 파일로 연결했습니다. `vision.py`는 임시 파일에 다 쓴 뒤 `os.replace`로 교체하므로, `assistant.py`가 쓰다 만 파일을 읽지 않습니다.

### 2. 이벤트 번호 (`event_id`)
`state.json`은 0.5초마다 갱신됩니다. 그래서 수업 코드처럼 파일 수정 시각만 보면 이벤트와 일반 갱신을 구분할 수 없습니다.
`vision.py`는 이벤트마다 번호를 1씩 올리고, `assistant.py`는 번호가 바뀌었을 때만 응답합니다.
또 10초(`EVENT_MAX_AGE`)보다 오래된 이벤트는 이미 지난 상황이므로 말하지 않습니다.

### 3. 이벤트 판정 (`focus_tracker.py`)
- **시간 기준:** 프레임 수가 아니라 초 단위로 판정하므로, FPS가 변해도 "3초"의 의미가 같습니다.
- **YOLO 놓침 허용:** 폰을 들고 있어도 YOLO가 몇 프레임씩 놓칩니다. 0.5초(`MISS_GRACE_SECONDS`)보다 짧게 끊긴 것은 계속 보인 것으로 칩니다.
- **한 번만 경고:** 폰을 내려놓거나 자리에 돌아올 때까지 같은 경고를 반복하지 않습니다.
- **집중 시간:** 사람이 보이고 폰 구간이 아닌 시간만 더합니다.

### 4. 소음 측정 (`voice.py`)
1초 녹음한 16-bit 샘플의 RMS(제곱 평균의 제곱근)로 평균 음량을 구하고, `20·log10(RMS / 32768)`로 dBFS를 계산합니다.
값은 0 dBFS가 최대이고, 조용할수록 큰 음수입니다.
- **오탐 방지:** 순간적인 소리(기침, 책 덮는 소리)에 반응하지 않도록 2번 연속 기준을 넘어야 이벤트로 봅니다.
- **자기 소리 제외:** 스피커로 말한 직후 3초는 자기 목소리를 재지 않도록 측정을 쉽니다.
- **마이크 공유:** STT와 소음 측정은 같은 프로세스에서 순서대로 마이크를 쓰므로 장치 충돌이 없습니다.

### 5. 프롬프트 (05 D, 06 A-5)
수업에서 배운 형식으로 프롬프트를 나눴습니다.
- **system:** `Instruction / Constraint / Output Format` 형식. 역할은 공부 도우미, 규칙은 "Context에 없는 것은 추측 금지", 출력은 두 문장 이내입니다.
- **user:** `Context`(탐지 물체 + 집중 통계를 한국어 문장으로 바꾼 것)와 이벤트별 요청 문장입니다.
- **클래스 이름:** 한국어로 바꿔 넣어 TTS가 자연스럽게 읽게 했습니다.

## 한계 및 개선 사항

### 1. 음성 처리: 겹치지 않는 대신 기다림
음성(녹음·STT·TTS)은 별도 프로세스가 아니라 `assistant.py` 안에서 **한 번에 하나씩** 실행됩니다.
그래서 목소리가 겹치지는 않습니다. 대신 말하거나 듣는 동안에는 다른 일을 하지 못합니다.

| 한계 | 원인 | 개선 방향 |
|---|---|---|
| **응답 중 이벤트 손실** | `state.json`에는 마지막 이벤트 하나만 저장됨. 응답하는 몇 초 사이에 이벤트가 두 번 생기면 앞의 것은 덮어써짐 | `vision.py`가 이벤트를 목록(큐)으로 쌓고 `assistant.py`가 차례로 처리 |
| **오래 걸린 응답 뒤 이벤트 무시** | 질문 처리(녹음 5초 + Whisper + Gemma + TTS)가 10초(`EVENT_MAX_AGE`)를 넘기면, 그 사이 생긴 phone/absent 이벤트는 오래된 것으로 보고 버림 | 이벤트 시각을 "생긴 시각"이 아니라 "처리를 시작할 수 있게 된 시각" 기준으로 판단 |
| **응답 끼어들기 불가** | Gemma가 말하는 중에는 새 상황(예: 폰을 또 듦)에 반응하지 못함 | 재생을 별도 프로세스로 분리하고, 더 중요한 이벤트가 오면 재생 중인 `aplay`를 멈춤 |
| **질문 시작 지연** | `s`를 눌렀을 때 소음을 재는 중이면 최대 1초 늦게 "네, 말씀하세요."가 나옴 | 소음 측정을 짧게 나누거나, 질문 요청이 오면 측정을 중단 |
| **여러 번 실행하면 목소리 겹침** | 실행 중 `main.py`를 한 번 더 켜면 Assistant가 2개가 되어 같은 이벤트에 동시에 말함 | 실행 시 잠금 파일(lock)로 중복 실행 방지. 지금은 다시 켜기 전에 기존 프로그램을 `q`로 종료해야 함 |

> 음성 출력을 따로 분리하지 않은 이유: 스피커가 하나라 말이 겹치면 안 되고, 분리하면 "스피커 소리를 마이크가 소음으로 재는" 문제를 따로 막아야 합니다. 지금은 말한 뒤 3초(`AFTER_SPEECH_DELAY`) 측정을 쉬는 것으로 간단히 막고 있습니다.

### 2. 오탐 (잘못된 감지)

| 이벤트 | 오탐 상황 | 원인 | 개선 방향 |
|---|---|---|---|
| `phone` | 책상에 놓아 둔 폰, 리모컨·계산기 같은 물체에도 경고 | 판정이 "폰이 화면에 보이는가"뿐이고, 손에 들었는지는 보지 않음. `CONF_THRESHOLD = 0.4`라 비슷한 물체도 잡힘 | 폰 BBox가 사람 BBox(손 위치)와 겹칠 때만 인정, 폰 클래스의 신뢰도 기준만 높이기 |
| `absent` | 고개를 숙이거나 몸을 화면 밖으로 기울였을 때, 어두운 조명에서 자리비움으로 판정 | YOLO가 사람을 10초 동안 못 찾으면 바로 자리비움 | 카메라 각도를 상반신이 다 보이게 고정, 판정 시간 늘리기, 사람 대신 의자·책상 영역의 변화도 함께 보기 |
| `absent` (미탐) | 학생이 없어도 뒤에 다른 사람이 지나가면 앉아 있는 것으로 판단 | 화면 어디든 `person`이 하나라도 보이면 "있음" | 책상 앞 영역(ROI) 안의 사람만 인정 |
| `noise` | 학생이 소리 내어 읽거나 질문하는 소리, 음악도 소음으로 판정 | dBFS는 **소리의 크기**만 재고 무슨 소리인지는 모름 | 소리 종류 구분(말소리/음악/잡음) 또는 질문 직후 일정 시간 측정 제외 |
| `noise` | 장소가 바뀌면 너무 자주 또는 전혀 경고하지 않음 | 기준값(`NOISE_THRESHOLD_DB = -28`)과 마이크 입력(`Mic 24`)을 한 방에서 실측해 정함. dBFS는 마이크 기준 상대값이라 환경마다 다름 | 시작할 때 몇 초간 조용한 상태를 재서 기준을 자동으로 정하기 (예: 평소 값 + 6 dB) |
| Gemma 응답 | 상황과 맞지 않는 말 (예: 자리비움인데 "다시 왔구나") | Gemma 4 E2B는 작은 모델이고 `TEMPERATURE = 0.7`이라 답이 매번 달라짐. 프롬프트에 "학생은 지금 자리에 없다"를 직접 적어 15번 테스트에서는 모두 정상이었지만 완전히 막는 것은 아님 | temperature 낮추기, 응답에 금지 표현이 있으면 `FALLBACK_REPLIES`로 바꾸기 |
| 질문 (STT) | 질문을 잘못 알아듣거나 뒷부분이 잘림 | Whisper `base` 모델의 한국어 인식 한계, 녹음 시간이 5초로 고정 | 더 큰 Whisper 모델(속도와 비교 필요), 말이 끝나면 녹음을 멈추는 무음 감지 |

### 3. 그 밖의 한계

| 한계 | 원인 | 개선 방향 |
|---|---|---|
| **카메라가 끊기면 전체 종료** | `cap.read()`가 실패하면 `vision.py`가 끝나고, `main.py`가 Assistant도 종료함. 전원 없는 USB 허브에 카메라·마이크·스피커를 함께 꽂으면 연결이 끊긴 적이 있음 | 카메라를 Jetson의 USB 3.0 포트에 직접 연결. 코드에서는 실패 시 몇 번 다시 열기 |
| **재시작 직후 이벤트 놓침 가능** | `assistant.py`는 시작할 때 `state.json`의 이벤트 번호를 "이미 처리함"으로 기억함. 이전 실행의 파일이 남아 있으면, 새 실행의 같은 번호 이벤트를 처리하지 않을 수 있음 | 이벤트 번호 대신 (실행 시작 시각, 번호)로 구분하거나, 시작할 때 `state.json` 삭제 |
| **마이크 설정이 유지되지 않음** | `amixer`로 올린 입력 크기는 재부팅하면 기본값(16)으로 돌아감 | 실행 전에 `amixer -c Microphone sset Mic 24`를 다시 실행 (실행 방법 1단계) |
